# OWN / FLOW v1.4.0 · Mission Control & Task Evidence

2026-11-11。完整静态部署包，`index.html` 在 ZIP 根目录。上传到现有 Cloudflare Pages 项目的 **Create deployment / 创建部署** 即可；无需构建命令、服务端、密钥或安装依赖。压缩包可直接上传，也可解压后上传其内容。不要额外套一层目录。

## 这次升级怎么体验

1. 打开 **战术工作室 → 任务规则与结构**。选择均衡分工、中路保护、主动上压或封线协同，便会启用任务控制。旧战术默认保留常规控制；需要主动选择任务预设。
2. 调整保守／激进、名义队形权重、任务跟踪增益和触发时间。逐球员设置上压、保护、封线、支援等偏好；在规则表中改变优先级、条件和下一状态。先启用预设，再运行比赛观察效果。
3. 点击 **查看任务与事件**。球员节点连接到实际分配的职责节点；选择球员，检查其任务状态链、局部证据、触发条件、交接等待和 ACK。配置中的职责与物理世界中是否到位分别显示。
4. 查看 **上压、封线与身后保护**。金色表示施压半径，薄荷绿表示球后保护区，虚线表示声明的传球路线，蓝色表示所选球员的真实任务参考。下面的阶段表同时报告任务跟踪、名义阵型、偏移一致性、限幅、压迫、区域覆盖、联合覆盖、路线准备和进攻接应。
5. 在 **事件记录与快照回放** 选择具体事件，查看当时的物理位置、状态转移、条件证据和策略版本。导出 HTML 获得可阅读、可打印的报告；导出 JSON 获得完整保留事件、快照和指标。
6. 进入 **多智能体工作台 → 交互辨识**。按夺回转换、丢球转换、持球组织、阵地防守或自由球筛选，再拟合。切换阶段会清除旧结果；短片段不足 40 个有效间隔时明确提示数据不足。拟合不会跨阶段拼接运动差分。
7. 在任务页点击 **从此处进行 A/B**。保存同一世界与记忆作为起点，比较关闭任务策略、保护优先、主动上压或封线方案。结果同时呈现控制代价、任务覆盖和足球事件，不能只看目标误差。
8. **控制实验室 → 个人控制器** 可检查任务参考进入闭环的路径和全部有符号指令分项。**控制训练场** 继续支持 P、PID、ADRC、MPC、拖拽接线、零极点和网络模态测试。其名义线性稳定性结论不自动推广到整场比赛。

四套任务设置也可通过战术资料库导入 `examples/MissionPolicies.json`。

## 关键判定边界

- 任务状态由每个球员的局部证据驱动；分析页面使用全局状态作评估。
- 保护者交接需要新鲜状态消息中的到位确认；视觉接近不等同于确认。这个协议仍可能因信息不一致产生重复分工或等待。
- 控球职责窗口固定期限和施压半径，修改策略不会重置它们。之后到位也不会抹去先前的期限未满足事件。
- 上压、封线、覆盖是明确的采样几何代理任务，不是保证截球或获胜的概率。一次失位、一次搜索失败或一次窗口未满足，都不被标记为不可避免的结构冲突。
- 共识误差小与完成足球任务是两种不同结果。策略改变参考时，任务跟踪误差也可能改变含义，必须并看名义阵型、职责和比赛结果。

详细模型、研究衔接、参数语义、交接与报告范围见 [MISSION_METHODS.md](maintenance/MISSION_METHODS.md)。研究依据为用户提供的 Football_Task_Study_v4 和任务规划／控制架构资料；未把私人研究原文放入部署包。

## 报告与数据

- 实时页面显示最近 60 个事件；HTML/JSON 保留最近 2,400 个并标明省略数量。阶段汇总覆盖整个已监测过程。长实验可定期导出。
- 存档记录任务记忆、在途消息、随机状态和固定窗口，恢复可确定性继续。
- 应用和新存档的引擎版本是 1.4.0。可读取 1.0.0、1.2.0、1.3.0 的兼容存档；旧存档从恢复时刻开始积累新任务统计，不补造过去事件。
- 保存数据按浏览器和网站来源隔离。继续使用原 Pages 项目地址便于保留本地设置；换新域名时应先导出战术和存档。

## 测试与复现

Node.js 20+ 环境下：

```sh
npm test
node maintenance/reproduce-mission.mjs maintenance/mission-browser-evidence.json
node maintenance/reproduce-network.mjs maintenance/network-browser-evidence.json
node maintenance/reproduce-mission-benchmark.mjs
```

network-browser-evidence.json 是 v1.3 的原始浏览器样本，用来检查兼容性。新的阶段辨识导出也可传给同一脚本，阶段选项会随报告一起重算。HTML 示例见 `maintenance/mission-report-example.html`。完整验收记录见 `maintenance/TEST_REPORT.md`。

| 模块 | 职责 |
|---|---|
| `mission-core.js` | 局部守卫、任务状态、参考、迟滞和保护交接 |
| `task-monitor.js` | 30 Hz 全局评估、固定窗口、分阶段汇总、事件记录 |
| `mission-studio.js`, `mission-view.js`, `mission.css` | 战术编辑、职责图、局部证据、历史快照及 HTML 报告 |
| `mas-model.js`, `mas-worker.js` | 阶段隔离的运动辨识、基线、秩与留出验证 |
| `engine.js`, `sim-worker.js`, `benchmark-worker.js` | 比赛动力学、存档、报告与配对策略干预 |
| `math-display.js` | 使用原生 HTML/SVG 上下标，避免依赖罕见修饰字形 |
| `maintenance/CONTROL_METHODS.md`, `maintenance/NETWORK_METHODS.md` | 控制训练场和运动辨识的详细方法 |
| `maintenance/FOOTBALL_SOURCES.md` | 经典球队资料来源与原创阵容说明 |

本次检查覆盖桌面和 375 px 窄屏内容容器、Canvas 兼容渲染、规则编辑、参数控制、节点联动、报告导出、事件回放、阶段拟合和 A/B。真实手机触控与硬件 WebGL 帧率仍需设备验收。全部运行资产、数学字体和渲染模块随包提供，不依赖外部 CDN。
